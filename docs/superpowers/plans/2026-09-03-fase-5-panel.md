# Fase 5 — Panel: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** El dueño de un negocio ve sus conversaciones en vivo, toma el control de una cuando hace falta, mide qué está pasando y edita el prompt de su asistente con red de seguridad; el super-admin ve lo mismo para todos los negocios.

**Architecture:** Next.js 15 consume la API de `apps/api` con sesión por cookie. El tiempo real va por WebSocket con salas por tenant: un mensaje nunca se emite a una sala que no sea la suya. La toma de control humano reutiliza el estado `handoff` que el motor de flujos ya maneja desde la Fase 1 — el panel no inventa un mecanismo nuevo, solo lo acciona.

**Tech Stack:** Next.js 15 (App Router), React 19, `@nestjs/websockets` + `socket.io`, Tailwind 4, Recharts.

**Spec:** `docs/superpowers/specs/2026-09-03-plataforma-whatsapp-citas-design.md`

**Depende de:** Fases 1-4 completas.

## Global Constraints

Además de las de las fases anteriores:

- **Ninguna consulta del panel escapa del tenant.** Toda ruta pasa por `runInTenant` con el tenant de la sesión, nunca con uno recibido del cliente. La única excepción es el rol `superadmin`, y esa excepción es explícita y auditada.
- **El WebSocket emite a salas por tenant.** `room = tenant:<id>`. Una fuga aquí es una fuga de conversaciones de clientes.
- **El panel nunca envía texto libre fuera de la ventana de 24 h.** Reutiliza `canSendFreeform` de la Fase 1 y deshabilita el campo de escritura con una explicación visible.
- Publicar un prompt exige haber corrido el banco de la Fase 4. La UI lo recuerda; no lo puede garantizar, así que lo deja registrado.
